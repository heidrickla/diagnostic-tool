# Third-party components in the local prototype

- `printpdf` 0.12.8 is MIT licensed: <https://github.com/fschutt/printpdf>. It is used for in-process PDF generation.
- `NotoSans-Regular.ttf` is bundled from the installed Noto Sans font. `assets/NotoSans-OFL.txt` contains the SIL Open Font License notice from [Google Fonts](https://github.com/google/fonts/blob/main/ofl/notosans/OFL.txt). Keep the notice with any distributed binary.
- `azul-simplecss` 0.2.3, a transitive dependency of printpdf's font/layout support, is MPL-2.0 licensed: <https://github.com/fschutt/simplecss>. A distributed binary needs the applicable MPL notice and a way to obtain source for covered files. No binary has been distributed.
- `flate2` 1.1 (MIT or Apache-2.0, <https://github.com/rust-lang/flate2-rs>) and `crc32fast` 1.5 (MIT or Apache-2.0, <https://github.com/srijs/rust-crc32fast>) are used by Check recovered files to decompress ZIP entries and PDF streams and test their CRC-32 checksums. Both were already in the dependency graph through `printpdf`; flate2's backends in the graph are `miniz_oxide` (MIT, Zlib or Apache-2.0, with `adler2`, 0BSD, MIT or Apache-2.0) and `zlib-rs` (Zlib).
- `rustls` 0.23.46 is used by the outbound HTTPS client code; `rcgen` 0.14.10 is a test-only dependency for the offline TLS fixture. The current release GUI has no remote connection. Recheck their licenses and transitive dependencies before release.
- `axum`, `reqwest`, `jsonwebtoken`, and the official `rmcp` Rust SDK support the disabled relay, outbound clients and MCP adapter. This is development source only. Audit their exact versions, feature sets, transitive licenses and distribution notices before shipping a support binary.
- The recovery key sign-in window (`src/recovery/keylookup/webview2.rs`) uses the Microsoft Edge WebView2 Runtime already installed on the PC (part of Windows 11); nothing of it ships with the exe. No crate was added for it. The binding is hand-written: the interface IDs and the order of the interface methods it calls come from Microsoft's WebView2 SDK header WebView2.h (read through the generated bindings of `webview2-com-sys` 0.39.1, MIT). The WebView2 SDK is licensed by Microsoft under a BSD-style licence ("Copyright (C) Microsoft Corporation. All rights reserved.", redistribution in source and binary forms with the notice kept); keep that notice with a distributed binary. The `webview2-com` crate was not used: it imports `WebView2Loader.dll` (raw-dylib), which would have to ship beside the exe and be loaded from its folder, against the one-exe build and /DEPENDENTLOADFLAG:0x800, and it brings the `windows` crate. The loader steps (the `EBWebView` registry value under EdgeUpdate\ClientState, then the runtime's `CreateWebViewEnvironmentWithOptionsInternal`) follow what Microsoft's loader does, as described by the OpenWebView2Loader project; no code was taken from it.

An earlier `cargo metadata --offline --format-version 1` review covered the PDF dependencies; the new transport and MCP dependency graph has not received a full license audit. Perform that audit before release.
